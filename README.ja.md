# Maboroshi

Maboroshi（幻、"phantom space"）— 並列に動くコーディングエージェントのためのワークスペース。

Maboroshi はローカルの Git ワークスペースを管理し、多数のコーディングエージェントと人間が、同じリポジトリで同時に独立して作業できるようにします。ワークスペースは、ひとつのリポジトリのひとつのチェックアウトに、Git が記録しない情報を加えたものです。名前、所有者、目的（プルリクエスト、issue、ベース）、観測した状態を扱います。現在、チェックアウトの実体は Git worktree です。

Rust での書き直しは `next` ブランチで開発しており、[GitHub Releases](https://github.com/phantompane/phantom/releases) で `v7.0.0-alpha` 系のプレリリースを配布しています（npm ではまだ配布していません）。従来の TypeScript 版は `main` ブランチに残しています。その README は <https://github.com/phantompane/phantom/blob/main/README.md> にあります。

## なぜ必要か

Git はコードとチェックアウトを記録します。しかし、誰がそのチェックアウトを担当しているのか、なぜ存在するのか、片付けてよいのかは記録しません。多くのエージェントが同じリポジトリで同時に作業すると、その答えが分からなくなります。Maboroshi は通常の Git の上で、その情報を補います。リポジトリもブランチも worktree も通常の Git のままで、`mabo` と一緒に `git` を直接使えます。

ワークスペースが分けるのはファイルとブランチであり、プロセス、ポート、データベース、認証情報ではありません。Maboroshi はワークスペースの境界と自身の操作を調整します。サービスを並行して動かすための準備は、プロジェクトとそのフックが担います。

## できること

Maboroshi はワークスペースを作成し、既存の作業を引き継いで準備し、ベースの変更に追従させ、片付けます。

- **確保と準備。** `clone` は ghq のディレクトリ構成でリポジトリを配置します。`create`、`attach`、`github checkout`（別名 `gh checkout`）は、作業ごとに専用の worktree を用意し、`.worktreeinclude` で指定した Git の無視対象ファイルをコピーして、信頼済みのリポジトリでプロジェクトフックを実行します。
- **情報の記録。** `meta set` で所有者、目的、関連するプルリクエストや issue、ベースを記録します。新しいワークスペースでは、`MABO_AGENT_ID` が設定されていれば所有者として使い、`--owner` があればそちらを優先します。所有者と目的は未設定のままにもできます。`list` と `where` で、何がどこにあるかを確認できます。
- **更新。** `sync` は fetch し、可能ならデフォルトブランチを fast-forward して、選択したワークスペースにベースの変更を取り込みます。未コミットの変更がある worktree はスキップし、分岐したデフォルトブランチの更新は拒否します。
- **片付け。** `gc` はマージ済みブランチ、クローズ済みのプルリクエスト、孤立したレコード、経過時間（`--older-than`）を根拠に対象を選びます。

コマンドは非対話で実行できます。`--json` の成功出力にはバージョン（`version`、`sync` では `schema`）がありますが、`project add` と `project remove` は例外で `{status, project}` を返します。エラーは構造化され、安定した終了コードも文書化されています（[Machine-readable JSON](README.md#machine-readable-json) を参照）。`exec` は代わりに、子コマンドの出力と終了コードをそのまま返します。人間も同じコマンドを使い、プレーンテキストの出力で操作します。

## デフォルトは安全、違うことをしたいときは明示する

- **マージ済み、所有者なし、古い、という状態は判断材料であり、削除してよいという許可ではありません。** `gc` は `--apply` または `--force` を指定するまで、削除予定を表示するだけです（`--force` は適用も兼ねます）。`--force` がなければ、未コミットの変更がある作業や、公開済みまたは取り込み済みと確認できないコミットを保護します。デフォルトブランチの worktree、実行中のカレントディレクトリがある worktree、Git でロックされた worktree は、`--force` があっても保護します。
- **所有者は情報であって、アクセス制御ではありません。** `MABO_AGENT_ID` が設定されているとき、`sync --mine` はそのエージェントのワークスペースを選び、`sync --all` は他のエージェントのものをスキップします。名前を明示すれば、所有者にかかわらず `sync` で同期できます。`gc` は他のエージェントのものでも、マージ済み、PR がクローズ済み、または孤立したワークスペースを対象にすることがあります。
- **push 済みの履歴は既定で保ちます。** 変更の取り込みが必要な場合、`sync` は公開済みの作業にベースをマージします。リベースには `--rebase --force` が必要です。ベースに含まれないコミットがひとつでも、既知のリモート追跡参照または fetch 先として設定された参照から到達可能なら、公開済みとして扱います。
- **非対話実行では、mabo 自身がプロンプトで入力を待つことはありません。** 空でない `MABO_AGENT_ID` または `CI` が設定されているとき、`--json` を指定したとき、標準入力または標準エラー出力が端末でないときが該当します。未信頼のフックを実行する必要がある操作は、リポジトリを変更する前に終了コード 1 で拒否します（JSON では `untrusted`）。`gc` は代わりに、そのフックが必要な削除をスキップし、スキップ自体はエラーにしません。`mabo trust --yes` で事前に信頼を記録するか、`--no-hooks` でフックを省略してください。Git の認証やプロジェクトのフックは、入力を求める場合があります。

## 目指さないこと

Maboroshi が担わない役割は次のとおりです。

- エージェントの実行やスケジューリング（起動、監視、割り当て）。
- タスク管理や PR ボット（担当の割り当て、レビュー、コメント、マージ）。
- 日常的な Git 操作の置き換え（コミット、push、履歴編集）。対象はベースの変更を取り込む操作に限ります。
- サンドボックスや実行環境の基盤（コンテナ、依存関係、シークレット、ポート、データベース）。プロジェクトフックを実行するだけです。
- 端末やセッションの管理（tmux、ペイン、ダッシュボード）。提供するのはパスです。
- セキュリティ上の隔離。所有者は協調のための情報であり、アクセスの境界ではありません。

コマンドの使い方・設定・JSON 出力の詳細は [README.md](README.md)（英語）を参照。
