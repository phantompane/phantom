# Maboroshi

**並列に動くコーディングエージェントのためのワークスペース。**

Maboroshi（幻、コマンド名 `mabo`）は、多数のコーディングエージェントと、一緒に働く人間が、同じリポジトリで互いの作業をぶつけずに同時に働くためのツールです。作業ごとに専用のワークスペースを用意します。その実体は Git worktree と、所有者・目的・ベースを記録するメタデータです。worktree は手段であり、目的ではありません。

Rust での書き直しは `next` ブランチで開発しており、[GitHub Releases](https://github.com/phantompane/phantom/releases) で `v7.0.0-alpha` 系のプレリリースを配布しています（npm ではまだ配布していません）。従来の TypeScript 版は `main` ブランチに残しています。その README は <https://github.com/phantompane/phantom/blob/main/README.md> にあります。

## なぜ必要か

Git は、ひとりがひとつの場所で作業することを前提としています。ひとつのリポジトリで10体のエージェントが並列に動くと、どの worktree が誰の作業なのか、作業は終わっているのか、安全に削除できるのか、最新の変更に追いついているのかが分からなくなります。Maboroshi は、通常の Git の上でその管理を引き受けます。リポジトリもブランチも worktree も通常の Git のままで、`mabo` と一緒に `git` を直接使えます。

## できること

Maboroshi はワークスペースの作成から片付けまでを管理します。

- **準備。** `clone` は ghq のディレクトリ構成でリポジトリを配置します。`create`、`attach`、`github checkout`（別名 `gh checkout`）は、作業ごとに専用の worktree を用意します。
- **所有者と目的の記録。** `meta set` で所有者、目的、関連するプルリクエストや issue、ベースを記録します。新しいワークスペースでは、`MABO_AGENT_ID` が設定されていれば所有者として使い、`--owner` があればそちらを優先します。所有者と目的は未設定のままにもできます。
- **最新の変更への追従。** `sync` は fetch してデフォルトブランチを fast-forward し、選択した worktree を更新します。未コミットの変更がある worktree はスキップし、分岐したデフォルトブランチの更新は拒否します。公開済みの worktree のコミットは既定でマージし、リベースするには `--rebase --force` が必要です。
- **安全性。** `create`、`attach`、`delete`、`sync`、`gc`、`github checkout` による Git とメタデータの変更は、リポジトリ単位の操作ロックを共有します。プロジェクトフックはそのロックの外で実行し、リポジトリへの信頼を必要とします。`mabo trust --yes` で事前に信頼を記録するか、`MABO_TRUST_ALL=1` でそのプロセスに限ってすべてのリポジトリを信頼できます。
- **片付け。** `gc` はマージ済み、PR がクローズ済み、または孤立したワークスペースを探します。`--older-than` を使えば古いものも対象にできます。`--apply` または `--force` を指定するまでは、削除予定を表示するだけです。`--force` がなければ、未コミットの変更がある worktree や、公開済みまたは取り込み済みと確認できないコミットを保護します。デフォルトブランチの worktree、実行中のカレントディレクトリがある worktree、Git でロックされた worktree は、`--force` があっても保護します。

## エージェントを第一に、人間にも

- `--json` で、バージョン付きの機械可読な出力と構造化エラーを取得できます（[Machine-readable JSON](README.md#machine-readable-json) を参照）。
- 終了コードは安定しており、ドキュメントに記載しています。
- 空でない `MABO_AGENT_ID` または `CI` が設定されているとき、`--json` を指定したとき、標準入力または標準エラー出力が端末でないときは、mabo は信頼を確認するプロンプトを出しません。未信頼のフックがある場合は、事前に信頼するか `--no-hooks` を指定します。人間が端末で操作するときは確認することがあります。Git の認証やユーザーが指定したフック・コマンドでは、入力を求められる場合があります。
- `MABO_AGENT_ID` を設定すると、新しいワークスペースの既定の所有者になります。`sync --mine` はそのエージェントのワークスペースを選び、`sync --all` は他のエージェントが所有するワークスペースをスキップします。ただし、名前を明示すれば他の所有者の worktree も同期できます。また `gc` は、他のエージェントのものでも、マージ済み、PR がクローズ済み、または孤立したワークスペースを対象にすることがあります。

人間も同じコマンドを使い、プレーンテキストの出力で操作します。

## 目指さないこと

- エージェントの実行やオーケストレーション。それは Codex、ボット、その他のツールの役割です。Maboroshi は作業のための安全な場所を提供します。
- CI やコードレビューの置き換え。
- 凝った人間向け UI。

コマンドの使い方・設定・JSON 出力の詳細は [README.md](README.md)（英語）を参照。
